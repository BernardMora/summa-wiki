A field guide · knowledge representation

Fourteen Ways to Draw an Ontology

Almost every ontology tool ever built draws the same picture: circles joined by lines. A survey of 37 OWL visualization tools found them mostly 2D, mostly node‑link, mostly showing only the class hierarchy — with color, size and shape barely used at all. That is a default, not a conclusion. Below, the same tiny ontology is drawn fourteen different ways, so the idioms can be compared rather than assumed.

Part one

The ladder the literature actually built

Dudáš, Lohmann, Svátek and Pavlov organise ontology visualization by dimensionality — a real ladder, from 1.5D text indentation up to 4D animation. Rungs six through eight have almost nothing standing on them.

Plate 01 / 1.5D / text + indentation

The indented list

The oldest and least glamorous idiom, and still the one most people actually use: Protégé's entity browser, a file tree, your note app's sidebar. The only graphical elements are text labels and indentation guides.

Reads
Strict containment, at any size. Familiar to everyone, trivially scannable, no layout algorithm to distrust. A controlled study by Fu et al. found indented trees beat node-link diagrams for list-checking tasks and for larger ontologies.
Breaks
One entity type at a time. Multiple inheritance only by duplicating a node. Non-taxonomic relations are invisible. Depth costs endless scrolling.

In the wildProtégé Entity Browser · every file manager ever built · Fu et al., “Indented Tree or Graph?” (ISWC 2013)

Plate 02 / 2D / the default

Node-link, and the layouts inside it

The overwhelming majority of ontology tools. Worth separating two decisions that usually get conflated: the notation (what a node's shape, fill and label mean) and the layout (where the algorithm puts it).

Almost nobody specifies the notation. VOWL is the exception — a real visual language that assigns graphical depictions to OWL constructs, deliberately designed to be readable by people who don't know OWL. It ships as WebVOWL and as a Protégé plugin.

Reads
Network structure, multiple inheritance, non-taxonomic relations, overviews of small ontologies. The only mainstream family that draws relations other than subsumption.
Breaks
Hairball past a few hundred nodes. Force layouts are unstable — re-run it and you get a different picture, which destroys the user's mental map. Labels collide; edge labels collide worse.

In the wildWebVOWL · Protégé OntoGraf & OWLViz · Graffoo (yEd/GraphML) · Cytoscape.js · vasturiano's force-graph family

Plate 03 / 2D / set-theoretic

Euler and Venn regions

The only family in this guide that draws the logic rather than the structure. A class is a region; a subclass is a region inside another; disjointness is two regions that don't touch; intersection is the literal overlap. Nothing has to be read off an edge label — the semantics are the geometry.

Reads
Set membership, subsumption, disjointness and overlap, all at once and without symbols. Excellent for explaining an axiom to someone who will never open a reasoner.
Breaks
Falls apart past a handful of classes. Worse: some set configurations are simply not drawable in the plane with simple closed curves, so the notation can refuse valid ontologies.

In the wildSWOOP · Venn/Euler layout research · the whiteboard, when someone is explaining a domain model to a client

Plate 04 / 2D / space-filling

Treemaps and nested containment

Zero wasted pixels. Every pixel of the canvas belongs to some class, and the area of a rectangle is proportional to the weight of its subtree — number of subclasses, number of instances, number of annotations, whatever you choose to map.

This is the family that answers a question node-link cannot: where is this ontology actually dense? Which branch has 4,000 classes and which has nine.

Reads
Relative magnitude across an entire large hierarchy, on one screen, with no scrolling and no layout instability.
Breaks
Depth is hard to count past three or four levels. Strict hierarchy only. Relations vanish entirely — a treemap has no edges to draw them on.

In the wildJambalaya / SHriMP (Protégé) · CropCircles · every disk-usage tool you have ever used

Plate 05 / 2D / the road not taken

The matrix

A cell per ordered pair. Nothing overlaps, nothing crosses, and density — the exact thing that kills node-link — is what a matrix is best at. Reorder the rows and columns by community and modular structure appears as visible blocks.

The 2018 survey explicitly flagged this as an opportunity: promising information-visualization methods, matrices and parallel coordinates among them, that ontology tooling has simply never picked up.

Reads
Dense relation sets, presence/absence at a glance, modular decomposition, symmetry and asymmetry of properties.
Breaks
Path-following is genuinely hard — you cannot trace a chain of subsumption by eye. Ordering is everything: a badly ordered matrix shows nothing at all.

In the wildAlmost no ontology tool · but standard in network analysis, and in 3D matrix-extension research

Plate 06 / 2.5D / terrain

The landscape

A 2D surface with a height field on it. Instead of drawing entities and relations, you draw a continuous terrain whose elevation encodes concentration and whose horizontal distance encodes similarity — the ThemeScape idea, applied to ontologies by exactly one experimental tool (Ontoviewer).

It is a near-empty rung on the ladder in the ontology literature, and it turns out to be the direct ancestor of the embedding maps in Plate 09 — which is the same idea, executed at a million points with learned coordinates.

Reads
Gestalt shape of a whole corpus. Where the mass is, where the empty regions are, which topics sit adjacent.
Breaks
Individual entities disappear into the surface. No relations, no logic, no drilling down without a second view.

In the wildOntoviewer (experimental) · ThemeScape / IN-SPIRE lineage · reborn as embedding cartography

Plate 07 / 3D / volumetric

Spheres, shells and volumes

Only two experimental tools in the survey — OntoSphere and OntoSELF. The pitch is more room: concentric shells give you a third channel for depth, and rotation lets you attack a cluster from an angle that untangles it.

The counter-argument is blunt: screens are 2D, so 3D always arrives via a projection, and projections both occlude and distort. The survey files this under visual lies — the class of misreadings that perspective makes easy and that flat diagrams make hard.

Reads
An extra encoding channel; local structure from a chosen viewpoint; genuinely more surface area for large graphs. Controlled studies find 3D more accurate for interpreting network structure.
Breaks
Occlusion, perspective distortion, navigation cost, no stable reference frame. The same studies find 2D better for spatial-memory tasks — you remember where things were on a flat map.

In the wildOntoSphere · OntoSELF · Onto3DViz · 3d-force-graph · 2D-search + 3D-view demos

Plate 08 / 4D / evolution

Ontology in time

The least-explored rung on the whole ladder. Ontologies are not static — classes get added, split, merged, deprecated — and almost no tool draws that.

There are two mappings, and they are not equivalent. Time-to-time is animation: play the versions as frames. It is intuitive but it wrecks the mental map, because an independently laid-out snapshot looks nothing like the previous one and the eye cannot match structures across frames. Time-to-space lays the versions out side by side, connected by linking and brushing — less immediate, far more reliable.

Reads
What changed, when, and by whose hand. Change as a first-class object rather than a diff you have to compute yourself.
Breaks
Animation destroys the mental map. Side-by-side eats screen. Both need a stable layout across versions, which force-directed layouts refuse to provide.

In the wildCODEX · Burch & Lohmann, “Visualizing the Evolution of Ontologies” · HOTVis for time-aware dynamic graphs

Part two

What escaped the lab

The interesting work of the last decade mostly did not happen inside ontology engineering. It happened in embeddings, in GPU rendering, in personal knowledge tools and in physics — and it produced idioms the OWL literature has not absorbed.

Plate 09 / learned coordinates / cartographic

The semantic map

Embed everything, project to two dimensions with UMAP or t-SNE, and render the result as terrain you can pan and zoom like a map. Position carries meaning, distance reads as similarity, density reads as popularity, and you can browse by wandering rather than by querying.

The exemplary hobby project is Anvaka's Map of Reddit: 176 million comments, Jaccard similarity between subreddits, clustered as a graph problem, then laid out as a map problem and served as tiles. The commercial version is Nomic Atlas, which does this at millions of points with automatic topic labels at several zoom levels.

Reads
Whole-corpus shape at a scale no node-link diagram reaches. Neighbourhoods, gaps, outliers, and topics you did not know you had.
Breaks
This is not an ontology, it is a similarity field. There are no typed edges, no axioms, no inheritance. Axes are meaningless, distances are not metric-faithful, and clusters can be artifacts of the projection rather than facts about the data.

In the wildanvaka's map tools (Reddit, GitHub, cities) · Nomic Atlas · UMAP / t-SNE / PCA

Plate 10 / non-Euclidean / focus + context

Hyperbolic space

The insight is geometric rather than graphical. A tree's node count grows exponentially with depth, and hyperbolic space's volume also grows exponentially with radius — so a hierarchy fits into hyperbolic space with far less distortion than into a flat plane. Put the root at the origin, and each level outward gets exponentially more room while occupying the same screen.

Focus-and-context comes free: drag any node to the centre and its neighbourhood expands while the rest of the ontology compresses toward the rim but never disappears. Nickel and Kiela's Poincaré embeddings made this a learning method too — they embedded the WordNet noun hierarchy this way — and it is now standard practice to optimise in the Lorentz model and visualise in the Poincaré ball.

Reads
Deep, wide hierarchies in constant screen space with the global context always present. Generality is literally centrality.
Breaks
It is a geometry people have to learn. Sibling distance is misleading to the untrained eye, and the rim is unreadable without navigating there.

In the wildH3 / hyperbolic browsers · Poincaré embeddings · CO-SNE for hyperbolic dimensionality reduction

Plate 11 / 2D / brute force

The million-node hairball

The engineering answer to scale. Cosmograph runs the entire force simulation on the GPU — not just the rendering — which is what makes million-node layouts interactive in a browser tab. Sigma.js takes the other route: WebGL rendering on top of graphology's algorithm library, so layout, metrics and community detection all live in the same stack.

The honest framing is that this is an aggregate view, not a reading view. It answers "how many communities, how connected, where are the bridges" and refuses to answer "what is this node." It needs a second, coordinated view to be useful — which is precisely the multiple-coordinated-views move the ontology surveys keep recommending and the tools keep not implementing.

Reads
Global topology at 105–106 nodes: community count, bridge structure, degree distribution, isolated components.
Breaks
Labels are impossible. Overplotting means visual density is not data density. Every question about a specific entity has to be answered somewhere else.

In the wildCosmograph · sigma.js + graphology · Gephi · Carina · Neo4j Bloom for the property-graph side

Plate 12 / 3D / embodied

Immersive and VR

Mostly built in Unity on top of SPARQL endpoints, and mostly research prototypes: VRige for social graphs, VR browsers for RDF and linked data, VR access to knowledge graphs for history research. The interaction gains are real — gesture-driven query and exploration lowers the technical bar compared to writing SPARQL.

The evidence is split in a useful way. 3D lets people interpret network structure more accurately; 2D wins on spatial memory, meaning people remember where things were on a flat map better than in a room. The consistently replicated finding is engagement, which matters for exploration and matters much less for analysis.

Reads
Large graph structure with head-tracked parallax doing the depth work no static projection can do. Scale and physicality.
Breaks
Headset friction, session length, no shared reference frame for collaboration, and worse spatial recall than a plain 2D map.

In the wildLinked-data exploration in VR · VRige · 3d-force-graph-vr · immersive overview+detail navigation

Plate 13 / 2D / spatial metaphor

Ontology as architecture

Give up the abstract graph and commit to a building. Wings are domains, halls are edge types, rooms are topics, tunnels are cross-domain links. The structure is expressed as architecture instead of asserted in a schema file, which means retrieval becomes navigation and recall borrows the human spatial memory that the method of loci has exploited for two thousand years.

This has become an active idea in LLM memory design, where the appeal is that both the model and the user can hold a floor plan in their head in a way that neither holds a 40,000-triple store. It is also the family with the most obvious catch.

Reads
Location, adjacency, and route. Excellent recall and orientation; a shared vocabulary — "the Plantae wing" — that non-technical collaborators use without training.
Breaks
The metaphor constrains the topology. Buildings are trees with a few tunnels; ontologies are not. Multiple inheritance has no architectural analogue, and once the plan and the graph disagree, the plan quietly wins.

In the wildSpatial metaphors for LLM memory · memory-palace systems · game-world knowledge bases · Obsidian Canvas used as a plan

Plate 14 / generative / process

Rewriting systems and simulation

The genuinely different one. In every other plate the ontology is a fixed thing and the visualization is a rendering of it. Here the ontology is a rule, and the picture is the structure that emerges from applying that rule repeatedly — you do not draw the ontology, you run it and look at what it grows.

The most developed version is Wolfram model hypergraph rewriting: repeatedly replace any subhypergraph matching the left-hand side with the right-hand side. The associated views are worth stealing even if you never touch the physics — the causal graph (what event enabled what), the branchial graph (which alternative histories are near each other), and the multiway graph of all possible rewrite orders at once.

Reads
Ontology as process. What a small set of rules implies at scale, which structures are reachable, and where different orderings converge or diverge.
Breaks
Almost nothing about it is standard, tooling is mostly Wolfram-bound, and it answers a different question than "what does my domain model contain."

In the wildWolfram Institute hypergraph rewriting · the Hypergraph paclet · metagraph rewriting for AGI knowledge

Part three

What the field still has not solved

These are not opinions — they are the findings the 37-tool survey landed on, and they have barely moved since.

Overview versus detail

The oldest unsolved problem: give an overview of a large ontology while still showing detail on demand. Most tools pick one and abandon the other.

Unused retinal channels

Color, size and shape are used with little variation. Diagrams throw away the encoding channels that information visualization has spent forty years validating.

OWL 2 coverage

Of 37 tools tested against a coverage benchmark, two implemented every construct — OWLGrEd and TopBraid. Most visualize a subset and silently drop the rest.

Anything large

Only five tools could load a large ontology at all — Ontodia, OntoGraf, Protégé's Entity Browser, TGViz and TopBraid. The rest choke or produce clutter.

Nobody evaluates

Very few empirical studies of whether any of these methods actually make people faster or more accurate. Tools are research prototypes; funding runs out before the user study.

Coordinated views

The obvious move nobody ships: a treemap for weight beside a node-link for structure beside an indented list for lookup, all linked and brushed. Every survey recommends it.

A reading path

  1. Open WebVOWL and drop in an OWL file. This is the default the whole field converged on — see it before you argue with it.
  2. Read the Dudáš–Lohmann–Svátek–Pavlov survey. It is the map of Part One, with the tool-by-tool coverage tables.
  3. Go to the opposite pole: browse anvaka's maps or a Nomic Atlas dataset. Learned coordinates, no schema, a million points.
  4. Read Poincaré Embeddings for the one genuinely different geometric idea — that the space should match the shape of the data.
  5. Run the Hypergraph rewriting paclet to see the only family where the picture is a simulation rather than a rendering.

The through-line: every one of these idioms is a projection, and each one drops something. Indented lists drop relations. Node-link drops scale. Treemaps drop edges. Embedding maps drop the axioms. Floor plans drop multiple inheritance. Hairballs drop identity. The question is never which representation is best — it is which loss you can afford for the question you are asking, and whether you have a second view that recovers it.
